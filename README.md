# Бешеные ракетки — сайт клуба

Одностраничный сайт клуба любителей бадминтона в Саратове: https://furiousrackets.ru/
Чистые HTML, CSS и JavaScript, без фреймворков и бэкенда.

Всё содержимое сайта редактируется в админке **Pages CMS** (https://app.pagescms.org)
без программиста. Админка сохраняет изменения в этот репозиторий, GitHub Actions собирает
данные и публикует сайт — примерно через минуту правка видна на сайте.

## Что где лежит

```
.pages.yml                 настройка админки: разделы, поля, русские подписи
content/                   содержимое сайта — его правит админка
  general.json             телефон
  networks/*.json          справочник «Соцсети» — название и ссылка
  schedule.json            расписание
  promos.json              акции
  tournaments.json         турниры (поля те же, что у акций)
  training-types/*.json    справочник «Виды тренировок» — по файлу на запись
  venues/*.json            справочник «Площадки»
  levels/*.json            справочник «Уровни игроков»
  coaches/*.json           справочник «Тренеры»
  hero.json, signup.json, partners.json, faq.json, final.json — остальные блоки
tools/build-content.mjs    сборка: content/ → site/data.json
tools/prerender.mjs        для поисковиков: site/ → dist/ (готовый HTML, sitemap.xml, schema.org)
site/                      публикуемая папка — это и есть сайт
  index.html
  css/style.css
  js/app.js                читает data.json и рисует блоки
  data.json                собирается автоматически, в git не хранится
  media/                   картинки, загруженные через админку
  assets/                  оформление: логотип, маскот, иконки — не для админки
  robots.txt               правила для поисковых роботов и ссылка на sitemap
.github/workflows/deploy.yml   сборка и публикация на GitHub Pages
```

## Как устроены данные

**1. Общие контакты — в одном месте.** В «Общем» два раздела:
- **Телефон** — один номер на весь сайт (шапка, окно «Записаться», «Приходи играть», `{телефон}`).
- **Соцсети** — просто список: название и ссылка. Где какие соцсети показывать, выбирается
  в самих блоках: «Запись → Окно «Записаться» → Соцсети в окне» и в «Приходи играть»
  (кнопки групп и ссылки в самом низу). Показываются в том порядке, в котором выбраны.

**Окно «Записаться».** Все кнопки «Записаться на тренировку» (под расписанием, первый экран,
плавающая кнопка на телефоне, кнопки акций и турниров без своей ссылки) открывают окно
с выбором: «Написать в …» для выбранных соцсетей и «Позвонить». Всё, что в окне написано,
и текст кнопки — в «Блоки сайта → Запись». Справа в шапке — «Позвонить» (на компьютере — номер).

**Расписание — неделей.** На компьютере — календарь как в Google Календаре: слева шкала времени
(от самого раннего начала до самого позднего конца), 7 колонок пн–вс, плитка стоит на своём
времени начала и заполняет свои ячейки — высота по длительности. Если тренировки в один день
пересекаются, плитки встают рядом. На телефоне неделя не помещается и листается вбок (с инерцией:
быстрый свайп долистывает до конца, медленный — до ближайшего дня): под
календарём стрелки по центру, у края, за которым есть ещё дни, — затемнение, шкала
времени остаётся на месте, при открытии сразу виден сегодняшний день.
Сегодняшний день (по саратовскому времени, считается в браузере у посетителя) помечен «сегодня».
В одном дне может быть несколько тренировок. Время — в одну строку,
конец мельче. Уровни — только нужные; если не выбраны — «все уровни». Карточка целиком в цвет вида
тренировки: «Виды тренировок → Цвет карточки в расписании» (салатовый, белый, голубой, серый, тёмный).
Площадка на карточке — ссылка на неё в «Где играем»; сама карточка не нажимается.

**Персональные — в общем расписании.** Это обычные строки с видом «Персональная», без площадки
(площадку можно не указывать — тогда её нет на карточке). Поле
**Занятия по, мин** делит строку на отдельные карточки: 18:00–22:00 и 60 → четыре карточки
18:00–19:00, 19:00–20:00, 20:00–21:00, 21:00–22:00. Отмена с временем (например, 19:00)
зачёркивает одно занятие. **Цена** 0 — цену не показывать (пусто — цена площадки). Уровней
у персональных нет — галочка «Без уровней в расписании» у вида тренировки. Запись — общая,
через «Записаться на тренировку».

**Отмены.** «Блоки сайта → Расписание → Отмены»: дата, время начала (пусто — весь день) и причина.
Если дата приходится на текущую неделю, тренировка в этот день зачёркнута с подписью
«отменена · праздник». Прошедшие отмены можно не удалять.

**Запись** («Блоки сайта → Запись») — под расписанием, за полоской: «Как записаться», шаги в ряд
и кнопка «Записаться на тренировку» по центру (открывает окно). Пункт «Запись» в меню ведёт сюда.
«Первая тренировка — бесплатно» — на первом экране, над заголовком («Главный экран → Слоган»).

**2. Свой контакт в блоке — только если он отличается от общего.** Поля, которые
начинаются со слова «Своя…/Свой…», заполняются, только когда нужен другой контакт.
Пустое поле = общий контакт.

| Где | Поле | Если пусто |
|---|---|---|
| Акции, Турниры | Своя ссылка кнопки | окно «Записаться» |
| Расписание | Цена | цена площадки из справочника (0 — без цены) |
| Площадки | Своя ссылка на карту | ссылка на Яндекс Карты по адресу |

**3. Справочники связаны с другими разделами, как таблицы в базе данных.**
В расписании вид тренировки, площадка и уровни не пишутся руками, а выбираются из списка:

- **Наши тренировки** (виды тренировок) → блок «Наши тренировки» и колонка «вид» в расписании.
  «Цвет карточки в расписании» — салатовый, белый, голубой, серый или тёмный; этим же цветом —
  полоска под фото в карточке «Наших тренировок».
- **Где играем** (площадки) → блок «Где играем», площадка в расписании, акциях и турнирах. Здесь же цена
  тренировки по умолчанию. Дни тренировок в карточке площадки сайт берёт из расписания.
- **Уровни игроков** → уровни в расписании (с подсказкой при наведении) и список
  с описаниями в ответе FAQ через `{уровни}`.
- **Тренеры** → блок «Тренер / Тренеры».

Переименовали площадку или вид тренировки в справочнике — название поменяется везде сразу.
Удалили запись справочника, на которую ссылается расписание, — строка останется без неё,
а сборка напишет предупреждение в логе GitHub Actions.

**4. Форматированный текст.** Описания, ответы, тексты акций и турниров — это поля
с визуальным редактором: жирный, курсив, списки, ссылки, подзаголовки. Хранятся в Markdown.
Картинки внутрь текста вставлять нельзя — для них есть отдельные поля.

**Подстановки** в форматированных текстах:

| Пишете | На сайте |
|---|---|
| `{телефон}` | номер из «Контактов», по нажатию — звонок |
| `{Telegram}`, `{MAX}`, `{ВКонтакте}`… | ссылка на соцсеть с таким названием из «Соцсетей» |
| `{уровни}` | отдельной строкой — список уровней с описаниями; внутри фразы — «E, E+, C…» |

## Как подключить Pages CMS (один раз)

1. Зайдите на https://app.pagescms.org и войдите через GitHub аккаунтом `furiousrackets`.
2. Разрешите приложению Pages CMS доступ к репозиторию `furiousrackets/furious-rackets-app`.
3. Чтобы админ клуба мог править сайт **без своего GitHub-аккаунта**, пригласите его по почте:
   репозиторий в Pages CMS → Collaborators → Invite collaborators → email.

## Как пользоваться админкой

- Меню слева повторяет сайт. «Общее» — то, что используется везде: «Телефон», «Соцсети»
  и «Уровни игроков». «Блоки сайта» — по пункту на каждый блок страницы
  в том же порядке: Главный экран, Наши тренировки, Расписание, Запись (строка под расписанием), Где играем,
  Тренеры, Акции, Турниры, Партнёры, Частые вопросы, Приходи играть.
- Значки в меню разные: лист — одна форма, стопка — список отдельных записей
  (их можно выбирать в других разделах, например площадку в расписании).
- **Акции** и **Турниры** — отдельные списки с одинаковыми полями (в `.pages.yml`
  это общий компонент `card`).
- В списках записи свёрнуты — нажмите, чтобы раскрыть. **Add an item** — добавить,
  значок корзины — удалить, перетаскивание — поменять порядок.
- В справочниках каждая запись открывается отдельно. Порядок на сайте задаёт поле
  «Порядок на сайте»: меньше число — раньше.
- Расписание на сайте само сортируется по дню недели и времени — добавлять строки можно
  в любом порядке.
- **Save** — сохранить. Через минуту изменения на сайте.
- «Показывать на сайте» — спрятать запись, не удаляя. «Показывать до» у акций и турниров —
  на следующий день запись сама исчезнет.
- Карточки сами раскладываются по числу записей: одна — во всю ширину, две — в две колонки,
  четыре — сеткой 2×2 и т. д.

Словарик кнопок: Save — сохранить, Add an item — добавить, Add an entry — новая запись
справочника, Delete — удалить, Media — картинки, Cancel — отмена.

## Как посмотреть локально

Нужен Node.js 20+ и Python (для простого сервера):

```bash
npm install        # один раз
npm start          # собрать data.json и запустить сервер на http://localhost:8000
npm run preview    # то же, но версия для публикации из dist/ — как увидит поисковик
```

Или по шагам: `npm run build`, затем `cd site && python3 -m http.server 8000`.
Сборка печатает предупреждения, если в данных что-то не так (например, ссылка на удалённую площадку).

Перед правками кода делайте `git pull`: админка коммитит в `main`.

## Публикация

При каждом push в `main` (в том числе при сохранении в Pages CMS) workflow
`.github/workflows/deploy.yml` устанавливает зависимости, собирает `site/data.json`
готовит папку `dist` для поисковиков (`npm run dist`) и публикует её. Запустить руками: Actions → Deploy to GitHub Pages → Run workflow.

Домен `furiousrackets.ru` подключён в Settings → Pages → Custom domain. Файл `CNAME`
не нужен: при публикации через Actions GitHub его не использует.

## Фото площадок

В админке: «Где играем» → площадка → **Фото**. На сайте они идут сеткой во всю ширину экрана:
первое — большое (например, общее фото), ещё четыре — поменьше (на телефоне — два), на последней
плитке «+N», если фото больше. У второй площадки сетка зеркальная.

Просмотр — на весь экран, в двух видах. С плитки «+N» открываются **все фото площадки маленькими
плитками**; нажатие на любую — это фото крупно, дальше листаются как карусель (стрелки, свайп,
клавиши ← →), кнопка в левом верхнем углу возвращает ко всем плиткам, крестик или Esc закрывают.
С остальных плиток сетки — сразу это фото крупно. Так же открываются фото из ленты.
Просмотр ведёт себя как отдельная страница: у него свой адрес (`#foto-sgmu` — все фото СГМУ,
`#foto-sgmu-7` — седьмое), кнопка «Назад» в браузере или на телефоне закрывает его и возвращает
на главную туда же, где был человек (из фото, открытого со всех плиток, — сначала к плиткам).
Ссылкой с таким адресом можно поделиться — по ней сайт откроется сразу на этом фото.

Если у площадки заполнена **Точка на карте** (широта и долгота, например `51.531542, 45.983106` —
в Яндекс Картах нажми на здание, координаты будут в карточке места), одна из маленьких клеток
сетки становится картой с точкой площадки: на компьютере — в верхнем углу (у второй площадки —
слева), на телефоне — рядом с фото под большим. Карта — обычные светлые плитки OpenStreetMap
(без рекламы и без ключей; подпись «© OpenStreetMap» обязательна). Сама карта
не двигается, чтобы не мешать листать страницу, а нажатие по ней открывает Яндекс Карты (там можно
построить маршрут), поэтому отдельной ссылки «Показать на карте» у такой площадки нет.
Виджет Яндекс Карт не подошёл: внизу у него рекламный баннер.

Карта грузится с серверов OpenStreetMap, а им нужен адрес страницы, откуда идёт запрос. Поэтому
если открыть `dist/index.html` двойным кликом (как файл), плитки могут не загрузиться — смотрите
через `npm run preview` (http://localhost:8000). На сайте всё работает. Те же координаты уходят в разметку schema.org (`geo`) — это помогает в поиске по картам.

**Лента фото** под первым экраном — «Лента фото» → **Фото ленты** в админке: ровно эти фото и в этом
порядке (файлы лежат в `site/media/strip/`); там же можно скрыть ленту. Если список пуст, лента собирается сама из фото площадок — все, кроме первого (общего),
и в браузере при каждом заходе в ней 18 случайных.

Фото можно
загружать как есть — сборка (`tools/build-content.mjs`, библиотека `sharp`) делает из каждого
WebP-копии шириной 320/640/1024/1600 px в `site/gen/` (в git не хранится), браузер берёт
подходящую по экрану, а грузятся они только когда человек долистал до блока.
Подписи (alt) собираются автоматически: «Бадминтон в Саратове — тренировка клуба…, <площадка>, фото N»;
фото также попадают в разметку schema.org и в `sitemap.xml` — для поиска по картинкам.

Если на фото узнаваемые люди — с ними стоит согласовать публикацию.

## Поисковики (Яндекс, Google)

Все блоки сайта рисует `site/js/app.js` из `data.json`. Чтобы поисковики видели текст
без JavaScript, при публикации `tools/prerender.mjs` запускает этот же `app.js` на сервере
и сохраняет уже заполненную страницу в `dist/index.html`. В браузере `app.js`, как и раньше,
загружает свежий `data.json` и перерисовывает блоки. Там же:

- в `<head>` добавляется разметка schema.org (`SportsClub`): название, телефон, цены,
  площадки с адресами, тренер, соцсети — всё берётся из админки;
- пишется `sitemap.xml` с датой сборки; `site/robots.txt` на него ссылается.

`<title>` и `<meta name="description">` — в `site/index.html`. В них должны оставаться
слова, по которым ищут: «бадминтон», «Саратов», «тренировки».

Если меняете разметку блоков в `app.js`, проверьте `npm run preview`: код должен работать
и в браузере, и в jsdom при сборке (без `IntersectionObserver` и сети).

### Что сделать один раз вне репозитория

1. **Домен.** В Рег.ру: домен оплачен, данные администратора подтверждены, DNS-серверы
   указаны. Записи: `A` для `@` → `185.199.108.153`, `185.199.109.153`, `185.199.110.153`,
   `185.199.111.153`; `CNAME` для `www` → `furiousrackets.github.io`.
   Проверка: `dig +short furiousrackets.ru` показывает эти адреса.
2. **HTTPS.** GitHub → Settings → Pages: Custom domain `furiousrackets.ru`, дождаться
   сертификата, включить **Enforce HTTPS**.
3. **Яндекс Вебмастер** (webmaster.yandex.ru): добавить `https://furiousrackets.ru/`,
   подтвердить права TXT-записью в DNS (или метатегом в `site/index.html`),
   «Региональность» → Саратов, «Файлы Sitemap» → `https://furiousrackets.ru/sitemap.xml`,
   «Переобход страниц» → главная.
4. **Google Search Console**: ресурс «Доменный» `furiousrackets.ru`, подтверждение TXT-записью
   в DNS, «Файлы Sitemap» → `sitemap.xml`, «Проверка URL» → «Запросить индексирование».
5. **Карты**: карточка клуба в Яндекс Бизнесе, 2ГИС и Google Business Profile — со ссылкой
   на сайт, телефоном и расписанием. По запросу «бадминтон саратов» Яндекс первым
   показывает организации на карте.
6. **Ссылки на сайт**: в описании групп Telegram, MAX и ВКонтакте.

## Для разработчика: как добавить поле или раздел

1. Опишите поле в `.pages.yml` (`name` — ключ в JSON, `label` — подпись для админа).
   Типы полей: https://pagescms.org/docs/configuration/content/fields/
   Повторяющиеся поля вынесены в `components` (show, order, rich, card).
2. Обработайте его в `tools/build-content.mjs` — там же связи со справочниками,
   подстановка общих контактов и Markdown.
3. Выведите в `site/js/app.js`. HTML из форматированных полей вставляйте только через
   `richHtml()` — она оставляет безопасные теги и ссылки.

Связь со справочником — поле `type: reference` с `value: "{name}"`: в данных хранится
имя файла записи (например `sgmu.json`), сборка по нему находит запись.
Не меняйте `name` существующих полей и имена файлов в справочниках — ссылки перестанут находиться.
